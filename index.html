AI agents that do real work

I wrote code by hand for most of my career, and I build with Claude Code every day now. What matters is what the agents are allowed to do, and the checks around them.

Agents that play the real build

Unit tests can't tell you that a new player gets stuck on day 2. So I built a QA harness that lets AI agents play the actual game through a virtual mouse and keyboard.

For the launch QA pass, five agents played as five kinds of players: the Impatient, the Newcomer, the Optimizer, the Breaker and the Marathoner. Round 1 came back with 95 issues. Each one had a screenshot, the full game state and the exact steps to reproduce it.

I fixed them, and the same five replayed their own issues on the new build. Round 2 confirmed 57 fixed and found 33 new ones.

$ tools/build.sh qa
$ play.py -p breaker launch --seed 4404 --size 1280x800
$ play.py -p breaker press "NEW GAME"
$ play.py -p breaker shot first-look   # the frame, as drawn
$ play.py -p breaker ui                # what can I click, and where
$ play.py -p breaker drag 600 400 700 450
$ play.py -p breaker until 2 06:00     # wait for day 2, 6 AM
$ play.py -p breaker state             # stock, people, alerts, errors
$ play.py -p breaker issue --kind bug \
    --title "A sleeper on a demolished cot sleeps on, drawn nowhere"

Commands from the harness. That last issue is real. The Breaker filed it in round 1 and it's fixed.

  1. The agentClaude Code reads the screenshot, decides what a player would do next, and files what looks wrong.
  2. A Python command lineLaunch, click, drag, type, wait for a game time, read the state. Every input is logged with its game time.
  3. The real gameA QA build in Unity and C# with a local server. Each agent gets its own port, seed, saves and settings.

Screenshots, the list of controls on screen, and the game state travel back the same way.

Agents inside the editor

Claude Code connects to the Unity Editor through MCP. It runs the tests, edits scenes and reads console errors on its own, so I don't have to copy errors into a chat window.

16 languages, checked

A Python tool extracts every player-facing string, translates what's missing in batches with a glossary, and the check fails on a missing string or a broken placeholder.

An art pipeline

Some of the art in my current games comes from an image model. A JSON spec holds my prompts and style guide, a script generates and cleans each asset, and I review and pick every piece.

What it buys

A week before launch I decided Home Sweet Bunker needed a late game where the bunker runs itself: vertical farms, rain tanks, a water plant and robots. I wrote the goal and the definition of done. The agents built it on a branch in two days, with art, sound and all 16 languages, and every test passed.

Then I raised the test bunker to 300 people and had an agent profile it. One stock-counting pass went from 14 ms to 0.09 ms.

The rules I hold the agents to

  • The tests pass before every commit
  • Secrets are never printed, written or committed
  • Anything public, like a Steam build or a store page, waits for my yes
  • I read every diff and play the build before I call anything done
