Exhibit B

AI agents that do real work

I build with Claude Code every day. What matters is what the agents are allowed to do, and the checks around them.

$ tools/build.sh qa
$ play.py -p breaker launch --seed 4404
$ play.py -p breaker press "NEW GAME"
$ play.py -p breaker shot first-look  # the frame, as drawn
$ play.py -p breaker ui               # what can I click?
$ play.py -p breaker drag 600 400 700 450
$ play.py -p breaker until 2 06:00    # wait for day 2, 6 AM
$ play.py -p breaker state            # stock, people, errors
$ play.py -p breaker issue --kind bug \
   --title "A sleeper on a demolished cot
            sleeps on, drawn nowhere"

Unit tests can't tell you that a new player gets stuck on day 2. So I built a harness that lets AI agents play the real build through a virtual mouse and keyboard, read the screen and the game state, and file what's wrong. That last issue is real. The Breaker found it, and it's fixed.

Agents inside the editor

Claude Code connects to the Unity Editor through MCP. It runs the tests, edits scenes and reads console errors on its own.

16 languages, checked

A Python tool pulls out every player-facing string, translates what's missing with a glossary, and fails the check on a missing string or a broken placeholder.

A late game in two days

A week before launch I wanted a late game where the bunker runs itself. I wrote the goal and what "done" means. The agents built it on a branch in two days and every test passed. Then one profiled the result and took a stock-counting pass from 14 ms to 0.09 ms.

Standing orders

The rules I hold the agents to.

  1. The tests pass before every commit.
  2. Secrets are never printed, written or committed.
  3. Anything public waits for my yes.
  4. I read every diff and play the build before anything is called done.
